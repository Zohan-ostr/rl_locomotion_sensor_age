# Навигация по коду

Запускайте команды из корня проекта. Основной маршрут — [README](../README.md).

| Задача | Точка входа |
|---|---|
| Установка CPU-окружения и ассетов | `setup.sh`, `verify_setup.py` |
| Свободная интерактивная симуляция | `launch_h1_sandbox.sh` |
| Ограниченная демонстрация 20 с | `launch_interactive_h1.sh` |
| Штатный baseline без пакетов | `run_h1_baseline.py` |
| Один эпизод с пакетами | `run_sensor_episode.py` |
| Новая пилотная серия | `run_pilot.py` |
| Последовательные стадии исследования M3 | `run_m3_study.py` |
| Обучение двух ridge-моделей M3 | `train_m3.py` |
| Статистика, рисунки и отчёт M3 | `analyze_m3.py` |
| Сводные рисунки и таблицы | `build_report_assets.py` |

`interactive_h1.py` реализует окно и управление. `sensor_age.py` — пакеты,
очереди, B1 и исходный M. `periodic_compensator.py` и
`hybrid_compensator.py` — выбранный M2.

`linear_compensator.py` — M3: причинная история доставленных пакетов,
команда/фаза, необязательная история ранее выданных действий и небольшой
NumPy-прогнозатор. `check_m3.py` проверяет причинность, свежую идентичность,
ограничения и согласованность суставного сегмента q/dq.
Рабочая модель выбирается через `configs/m3_profile.json`.
`check_m3_reproduction.py` повторяет старый seed 10/J40 для B1/M/M2 и
проверяет совпадение M3 CLI с закрытым seed 100/I80. Это технические
повторы в отдельном каталоге, не дополнительные независимые наблюдения.

`run_m3_study.py` использует канонический каталог `results/m3_h1/`;
стадии `diagnostics`, `collect`, `tune`, `freeze`, `test`, `extensions`
сохраняют и возобновляют завершённые эпизоды. После `freeze` стадии проверки
требуют совпадения хешей исходников и модели. Повтор `test` на уже открытых
seed не создаёт новой независимой проверки. Для одного нового эпизода
используйте `run_sensor_episode.py --method M3` и новый каталог вывода.

`history_compensator.py`, `cycle_compensator.py`, `conservative_compensator.py`
содержат проверенные альтернативы, в том числе неудачные. Они остаются
для воспроизводимости подбора; их использует фабрика вариантов runner.

`check_*.py` — проверки математики, пакетов, baseline и управления.
`check_report_assets.py` проверяет SHA-256 и таблицы сводного отчёта,
а при наличии технических повторов — совпадение их сигналов.
`tune_*.py`, `validate_m2.py` — исторические стадии исследования M2.
Последний скрипт использует фиксированные исследовательские каталоги:
не запускайте его как быстрый пример и не перезаписывайте сохранённые серии.

`summarize_pilot.py`, `plot_pilot.py`, `analyze_m2.py`, `report_m2.py`,
`plot_m2_comparison.py` — анализ отдельных этапов.
`record_pilot_examples.py` — визуальные повторы, `check_m2_frontend.py` —
проверка совпадения сохранённых CLI/headless/GUI-траекторий.
