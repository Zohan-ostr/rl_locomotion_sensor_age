# Сенсорные очереди, компенсатор и пилот H1 на CPU

8 октября 2026. Второй практический этап завершён. Реализованы причинная
доставка двух потоков, удержание последних показаний B1, ограниченный
кинематический компенсатор M и диагностические B2/AJ/AI. В пилоте **снижения
числа падений у M не обнаружено**. Закрытые seed 100–139 не использовались;
гипотеза остаётся непроверенной на независимой серии.

## Выполненные проверки

- Все 14 unit-проверок причинности и математики прошли, см. `unit_checks.log`.
- Три интеграционных эпизода без начальных возмущений: E0 B0/B1/M дали
  побитово одинаковые наблюдения, действия и физические показания. Положение,
  ориентация и скорости B0 совпали с первым baseline точно; отличие временных
  меток ≈2×10⁻¹² с связано с `step*dt` вместо накопленного времени.
- Выполнены 548 пилотных эпизодов seed 0–9: 270 основной части и 278
  дополнительных. После каждого выполнен аудит доставленных значений и меток.
- Парность начальных состояний и расписаний подтверждена для 200 групп
  «seed × условие». Свежий разгон всех методов и условий совпал побитово;
  полная E0-identity подтверждена для всех 10 пилотных seed.
- Во всех эпизодах одинаковы commit, веса, XML/меши, YAML контроллера,
  порядок суставов и размеры 41→10. Соответствие первому этапу проверено
  по SHA-256 и конфигурации. Предупреждений MuJoCo нет.
- Два визуальных повтора seed 0/J80: физика, входы и действия сети побитово
  совпали с headless. Видео и просмотренные кадры подтверждают падение.
  Повторы не увеличивают N. Seed 0 задан до пилота; J80 выбран для разбора
  наблюдённой неустойчивости. Этот пример не служит статистическим доказательством.

548 эпизодов включают все испробованные горизонты. Сводка выбранных параметров
содержит 428 эпизодов; остальные 120 — дополнительные кандидаты горизонта,
сохранённые в `episodes.csv`, а не исключённые как неудачные. Из 428 эпизодов
18 диагностических выполнены только на seed 0 (N=1 для каждой точки).
Ошибок исполнения и исключённых эпизодов нет. Падения сохранены как результаты.

## Условия и доступ к данным

CPU Intel i9-12900H, Python 3.10.12, CPU PyTorch 2.5.1+cpu, MuJoCo 3.2.7,
NumPy 1.26.4; OMP/OpenBLAS/MKL и Torch intra-op — 1, inter-op — 1.
NVIDIA/CUDA и обучение не использовались. Окружение — проектное `.venv`;
`python -I` исключает ROS `PYTHONPATH`. Commit:
`276801e46c5d433564f24658bac64f254b7d2d4b`. Веса, SHA-256 и BSD-лицензия —
как в [первом этапе](../baseline_h1/REPORT.md). Зависимости с Matplotlib
для графиков — `requirements.lock.txt`.

Команда `[0.5,0,0]`, ровный штатный пол; dt=2 мс, политика 50 Гц,
максимальная длительность 20 с. Начальные суставные возмущения ±0,003 рад
созданы заранее и одинаковы между методами. LSTM загружается заново каждый
эпизод; shape probe не изменяет исходную память. PD использует свежие
локальные q/dq. Задержки относятся только к входу политики.

Два потока измеряются каждые 20 мс; до t=2 с включительно данные свежие.
Сбои действуют с t=2,02 с. Выбирается самый новый из уже доставленных
sample time. Потеря означает отсутствие пакета; старые приходы отбрасываются,
возраст растёт от последнего sample time. Компенсатор получает только
доставленные payload и возраста, горизонты и постоянные XML-модели.
Текущее состояние физики ему недоступно. Предсказание в физических единицах
предшествует исходной нормализации.

Номинальная высота pelvis уточнена **до пилота** по реальному baseline:
1,0329874238443275 м. Порог высоты — 0,6197924543065965 м;
крен/тангаж — 60° непрерывно 0,2 с. После подтверждённого падения эпизод
останавливается. Это кандидат правила для закрытой серии. Разбор двух видео
поддерживает его интерпретацию для показанных случаев; остальные падения
визуально не проверялись. Из 548 эпизодов 106 имели контакт pelvis с полом.

Полная семантика — [описание реализации](../../docs/README.md#sensor_age_implementation).
`configs/protocol.yaml` остаётся исходной спецификацией; исполненный пилот
описан в `configs/pilot.yaml`, `plan.json` и `extensions_plan.json`.

## Выбор горизонтов

Для каждого потока горизонт выбирался по его трём E2-условиям и seed 0–9:
меньше падений, затем больше среднее T_alive, затем меньше среднее RMSE
скорости. Правило сохранено до запусков в `configs/pilot.yaml`.
В этих условиях второй блок свежий, поэтому результат не зависит от его
горизонта; три общих горизонта покрывают девять пар без повторения идентичных
эпизодов. Для смешанных задержек это не предполагается.

| Поток | H, мс | Падения / N | Среднее T_alive, с | Среднее RMSE скорости, м/с |
|---|---:|---:|---:|---:|
| Суставы | 20 | 9/30 | 17,112 | 0,329 |
| Суставы | 40 | 10/30 | 15,469 | 0,397 |
| Суставы | 80 | 10/30 | 14,904 | 0,373 |
| IMU | 20 | 10/30 | 15,402 | 0,326 |
| IMU | 40 | 10/30 | 14,651 | 0,383 |
| IMU | 80 | 10/30 | 14,547 | 0,260 |

Рекомендованы **H_J=20 мс, H_I=20 мс**. Для IMU больший горизонт дал меньшее
RMSE на укороченных аварийных траекториях, но более короткое T_alive;
по заранее заданному правилу выбран 20 мс. Подбор не выполнялся по test seed
или отдельно под каждую задержку. E1/E3/E4 выполнены после выбора параметров
и не использованы для повторного подбора.

## Основные шесть условий E2

| Условие | B1 падения / N | M падения / N | B1 / M среднее T_alive, с | B1 / M RMSE, м/с |
|---|---:|---:|---:|---:|
| J20 | 0/10 | 0/10 | 20 / 20 | 0,147 / 0,171 |
| J40 | 0/10 | 0/10 | 20 / 20 | 0,152 / 0,183 |
| J80 | 8/10 | 9/10 | 10,656 / 11,337 | 0,724 / 0,632 |
| I20 | 0/10 | 0/10 | 20 / 20 | 0,158 / 0,146 |
| I40 | 0/10 | 0/10 | 20 / 20 | 0,175 / 0,158 |
| I80 | 10/10 | 10/10 | 6,249 / 6,207 | 0,672 / 0,675 |

По шести равно взвешенным условиям: B1 **18/60 (30%)**, M **19/60 (31,67%)**.
Парная разность B1−M = **−1,67 процентного пункта**. Описательный 95% интервал
bootstrap с повторной выборкой seed целиком: **[−6,67; +3,33] п.п.**,
5000 повторов, RNG seed 20261008. Интервал включает ноль; пилот не показывает
выигрыша по основной метрике. Эти же seed использовались для выбора горизонта,
поэтому результат и интервал не являются независимой проверкой гипотезы.
`hypothesis_supported` оставлен null, закрытая серия не выполнена.

Успешная ходьба: 40/60 у обоих методов. В J80 даже непавшие эпизоды не прошли
RMSE≤0,2 м/с. RMSE аварийных эпизодов рассчитывается до подтверждённого падения
и имеет смещение из-за разной длины траекторий; он показывается вместе
с T_alive и падениями.

В J20/J40 M уменьшил измеренную ошибку положений суставов в собственных
траекториях (0,0212→0,0095 рад и 0,0427→0,0272 рад), а RMSE скорости вырос.
В I20/I40 угловая ошибка гравитации и RMSE скорости уменьшились.
Это дополнительные наблюдения пилота. Траектории методов различаются;
эти сравнения не являются оценкой на одном записанном движении и не
устанавливают причину изменения устойчивости.

## Дополнительные условия

- E0: все B0/B1/M прошли 10/10, RMSE≈0,147 м/с; identity точная.
- E1, равные задержки: 20/40 мс — 0/10 падений у обоих; 80/120 мс —
  10/10 у обоих. Снижения числа падений у M нет.
- E3, одна серия 1/2/4/6 потерянных пакетов каждого потока: B1 и M
  прошли 80/80 каждый. Максимальный возраст при шести пропусках — 120 мс.
  Это кратковременное устаревание; результат не переносится автоматически
  на постоянную задержку той же величины.
- E4, независимые задержки 0/20/40 мс: оба прошли 10/10, RMSE B1/M
  0,145/0,161 м/с. Перестановка доставки реально наблюдалась: на seed 0
  отвергнуты 105 старых суставных и 96 IMU-пакетов у обоих методов.
- B2/AJ/AI: шесть E2-условий, только seed 0; N=1 для каждой точки.
  Общие выводы о превосходстве по одиночным случаям не делаются.

Полные таблицы — [TABLES.md](REPORT.md#tables), группы — `groups.csv`, все горизонты
и эпизоды — `episodes.csv`. Для каждой точки в `summary.json` сохранён
Wilson 95%; при N=10 и 0 падений верхняя граница ≈27,75%, поэтому нулевой
пилотный счётчик не означает нулевую вероятность падения. Область вывода —
эта H1-политика и модель сбоев; перенос на реального робота не проверялся.

## Воспроизведение и параметры следующего этапа

в подготовленном окружении, с новым каталогом вывода:

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv/bin/python -I scripts/run_sensor_episode.py \
  --initial results/pilot_h1/inputs/seed_0/initial.json \
  --schedule results/pilot_h1/inputs/seed_0/J80.json \
  --method M --horizon-joints-ms 20 --horizon-imu-ms 20 \
  --output results/my_sensor_episode
```

Для видео добавить `MUJOCO_GL=egl LIBGL_ALWAYS_SOFTWARE=1` и `--video`.
Полный пилот: `scripts/run_pilot.py --stage prepare --output results/new_pilot`,
затем последовательно validate, primary и extensions с тем же `--output`.
Существующие эпизоды не перезаписываются.

Рекомендация сохранена в `configs/test_candidate.yaml`: H_J/H_I=20/20 мс,
текущий критерий pelvis, 20 с, разгон 2 с, прежние шесть E2-условий,
±0,003 рад, парные состояния и расписания, 40 seed 100–139. Основная
E2-серия — 480 эпизодов. По времени 120 выбранных E2-эпизодов (148,02 с)
ожидаемое время такой серии ≈592 с, то есть **9,9 мин** без видео и расширений.
Это оценка объёма, не результат ещё не выполненных запусков.

Тестовый кандидат не заморожен и не запущен. Технических блокеров нет.
Основная нерешённая задача — отсутствие пилотного выигрыша по падениям;
независимая серия должна оценивать фиксированный метод с сохранением
отрицательных результатов.
